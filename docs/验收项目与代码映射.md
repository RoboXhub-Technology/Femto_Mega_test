# 验收项目与代码映射

## 1 深度 FOV

`survey` 对每个 Depth `VideoStreamProfile` 调用 `getIntrinsic()`，记录 width、height、fx、fy，并按验收表公式计算：

```text
HFOV = 2 * atan(width  / (2 * fx)) * 180 / pi
VFOV = 2 * atan(height / (2 * fy)) * 180 / pi
```

1024 x 1024 标记为 WFOV unbinned，640 x 576 标记为 NFOV unbinned。由于 Femto Mega 原始深度图有镜头畸变，内参公式结果应与已知距离标尺平面的几何法相互复核。

## 2 深度分辨率和帧率

`survey` 先从 SDK 枚举能力，`contract_profile_matrix.csv` 不会用相近配置替代缺失配置。`stream` 实际启动选定 profile，以硬件时间戳计算平均 FPS，以帧序号缺口估算掉帧。

实测 FPS 是全时段平均值，不是 UI 瞬时数字。

## 3 工作距离

`stream` 对中心正方形 ROI 读取 16-bit 深度值，乘以 `DepthFrame::getValueScale()` 转成 mm。每帧输出：

- 非零深度像素数和比例。
- 非零深度中位数。
- 硬件时间戳和帧序号。

相机无法自己知道测试板的物理位置，所以近端/远端仍需卷尺或激光测距仪定位。

## 4 1 m 相对精度

对 300 帧的中心 100 x 100 ROI，先求每帧非零深度中位数，再对所有帧的中位数取平均得到 Dmean：

```text
E = abs(Dmean - 1000) / 1000 * 100%
```

程序将 `E <= 0.15%` 输出为布尔值，最终合同判定仍以签署文本对“至少满足”的解释为准。

## 5 RGB 分辨率和帧率

`survey` 查找 3840 x 2160 @ 30 fps，`stream --sensor color` 实际运行并可保存第一帧。MJPG 帧保存为 `.jpg`，其他格式保存为 `.bin`；原始文件需结合 `stream_summary.json` 中的 format 解码。

## 6 RGB FOV

`survey` 用与深度相同的公式计算 Color profile FOV。验收时选取 3840 x 2160 profile 的记录。

## 7 RGB HDR

`hdr --set query` 查询 `OB_PROP_COLOR_HDR_BOOL` 是否可读/可写。`on` 和 `off` 会对相机执行显式属性写操作并回读。不将深度 HDR、自动曝光或背光补偿当作 RGB HDR。

## 8 最大功耗

`load` 按像素率 `width * height * fps` 为 Depth 和 Color 各选一个最高 profile，并同时打开 IMU。如设备不支持这个组合，先从 `survey` 选定可同时工作的 profile index，通过 `--depth-profile-index` 和 `--color-profile-index` 指定。

瓦数必须使用外部仪表测量，并保留功率曲线。

## 9 SDK 与 K4A Wrapper

`survey_summary.json` 记录 SDK、固件和设备信息；`stream` 证明 Orbbec SDK v2 能稳定取流。`k4a_wrapper_smoke` 是独立的可选程序，使用 K4A API 打开 4K RGB、NFOV unbinned Depth 并验证同步 capture。

## 10 IMU

`imu` 同时开启加速度计和陀螺仪，输出 x/y/z、温度、硬件/系统时间戳、帧序号，并分别计算实测采样率与帧序号缺口。
